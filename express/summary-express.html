01 / SNAPSHOT

Dự án đang có gì?

Đây là một ứng dụng Todo full-stack nhỏ: frontend thuần HTML/CSS/JS, Express 5 làm HTTP server, JWT làm access token và SQLite lưu dữ liệu.

4npm package trực tiếp
108package entry trong lockfile
2bảng SQLite: users, todos
7route chính tính cả trang chủ

Source of truth hiện tại: src/db.js định nghĩa schema, src/server.js ghép middleware/router, còn public/index.html vừa render UI vừa giữ toàn bộ state và fetch logic phía trình duyệt.

03 / SOURCE MAP

Mỗi file sở hữu một phần của hệ thống.

Đọc dự án theo trách nhiệm giúp tránh đặt validation, authentication hay SQL sai tầng.

src/server.js

Composition root: tạo app, gắn JSON/static middleware, mount router và mở port.

src/db.js

Database boundary: mở file SQLite và bảo đảm hai bảng tồn tại.

src/routers/authRouters.js

Use case đăng ký/đăng nhập: validate input, bcrypt, SQL và phát JWT.

src/middleware/authMiddleware.js

Security gate: đọc token, verify chữ ký/hạn dùng, kiểm tra user còn tồn tại và gắn req.userId.

src/routers/todoRouters.js

CRUD Todo cho user đã xác thực.

public/index.html

UI, state trong memory, localStorage token, fetch và render Todo.

public/styles.css

Layout riêng của ứng dụng Todo.

public/fanta.css

Base design system: màu, typography, button, input và responsive defaults.

todo.rest

Bộ request thủ công cho register, login và CRUD Todo.

test.rest

todo.db

05 / DATA FLOWS

Bốn luồng cần hiểu trước khi sửa.

Mỗi luồng mô tả input, boundary chịu trách nhiệm, state thay đổi và response trở về UI.

Đăng ký tài khoản

01Browser

POST JSON gồm username và password tới /auth/register.

02Express JSON

Chuyển request body thành req.body. Header phải là Content-Type: application/json.

03Validation

Từ chối username rỗng và password ngắn hơn 8 ký tự.

04bcrypt

Biến password thành hash một chiều trước khi lưu.

05SQLite

Tạo user, lấy lastInsertRowid, rồi tạo Todo mặc định dùng ID đó.

06JWT

Ký payload { id } với JWT_SECRET, hết hạn sau 24 giờ.

07Response

Trả 201 cùng token; browser lưu token vào localStorage.

Đăng nhập

01Lookup

Tìm user theo username bằng prepared statement.

02Compare

bcrypt.compareSync so password nhập vào với hash trong database.

03Issue token

Nếu khớp, tạo JWT mới và trả về browser.

04Dashboard

Browser lưu token, fetch danh sách Todo và render giao diện đã xác thực.

07 / ISSUE LOG

Lỗi đã gặp, nguyên nhân và bài học.

Mở từng mục để xem symptom → root cause → fix. Trạng thái phản ánh source hiện tại tại thời điểm tạo tài liệu.

Đã sửaESM không tìm thấy moduleERR_MODULE_NOT_FOUND cho authRouters hoặc db

Nguyên nhânProject dùng "type": "module"; relative import của Node ESM cần đuôi .js.

Cách sửaDùng ./routers/authRouters.js và ../db.js. Luôn kiểm tra path, casing và extension.

Đã sửareq.body là undefinedCannot destructure username hoặc bcrypt nhận undefined

Nguyên nhânexpress.json() bị comment hoặc được đặt sau router.

Cách sửaGắn app.use(express.json()) trước app.use('/auth', ...); vẫn phải validate runtime input.

Đã sửaREST Client không parse bodyHeader token error hoặc “Task is required” dù có task

Nguyên nhânDùng HTTPS với HTTP server, thiếu dòng trống, sai Content-Type hoặc không có ### giữa request.

Cách sửaDùng HTTP, header đúng chính tả, một dòng trống trước JSON và tách request bằng ###.

Đã sửaSai HTTP method404 Cannot POST /auth/login

Nguyên nhânClient gửi POST trong khi router từng khai báo GET.

Cách sửaĐăng nhập dùng router.post('/login'). Method và path phải khớp ở cả hai phía.

Đã sửaSQL INSERT sai cú phápnear “VALUE” hoặc near “)” syntax error

Nguyên nhânDùng VALUE, thiếu placeholder hoặc gọi bảng singular/plural không thống nhất.

Cách sửaDùng INSERT INTO users (...) VALUES (?, ?); thống nhất users và todos.

Đã sửaGửi response hai lầnERR_HTTP_HEADERS_SENT sau register

Nguyên nhânres.json() xong vẫn chạy tới res.sendStatus().

Cách sửaMỗi branch chỉ gửi một response và return res.status(201).json({ token }).

Đã sửaFrontend và server lệch URLAuth thành công nhưng dashboard không hiện

Nguyên nhânFrontend fetch /todos, server từng mount /todo.

Cách sửaThống nhất resource plural /todos cho cả frontend, REST file và server.

Đã sửaSQLite parameter 2 không bind đượcProvided value cannot be bound to SQLite parameter 2

Nguyên nhânHeader từng viết sai khiến task thành undefined; parameter 2 chính là task.

Cách sửaSửa Content-Type và validate typeof task === 'string' trước SQL.

Đã sửaJSON có trailing commaExpected double-quoted property name

Nguyên nhânJSON không cho phép dấu phẩy sau property cuối cùng.

Cách sửaBỏ dấu phẩy trước }. Phân biệt object literal JavaScript và JSON wire format.

Đã sửaForeign key thất bại sau restartJWT id tồn tại nhưng users row không còn

Nguyên nhânDatabase từng dùng :memory: trong khi token sống 24 giờ; restart xóa user nhưng token còn.

Cách sửaChuyển sang todo.db, dùng IF NOT EXISTS và middleware kiểm tra user vẫn tồn tại.

Đã sửaAdd Todo che giấu lỗiInput bị xóa dù POST thất bại

Nguyên nhânFrontend từng không kiểm tra response.ok.

Cách sửaParse response, throw khi không OK, chỉ clear input sau 201 và hiển thị message có ích.

Đã sửaLogout chưa có behaviorToken và dashboard vẫn còn sau khi bấm

Nguyên nhânlogout() ban đầu chỉ là placeholder.

Cách sửaXóa localStorage token, reset state/form, ẩn dashboard và hiện login screen.

Môi trườngSQLite ExperimentalWarningStack trace dài trong Node 22

Nguyên nhânnode:sqlite còn experimental trong Node 22; --trace-warnings từng mở toàn bộ stack.

Cách sửaKhông xem đây là app crash. Giữ Node 22 hiện dùng; bỏ trace nếu chỉ muốn log ngắn. Không đổi Node mù quáng.

Môi trườngNhiều Node installationdyld thiếu ICU khi chọn “system”

Nguyên nhân.zshrc ưu tiên Homebrew Node 14 cũ, liên kết tới ICU đã bị thay.

Cách sửaDùng NVM Node 22 đã xác minh. Gỡ PATH Node 14 chỉ sau khi review shell config; không tạo symlink ICU giả.

Môi trườngnpm config warningUnknown user config tarball/node_gyp/msvs_version

Nguyên nhânBa key cũ nằm trong user-level ~/.npmrc, không phải package.json dự án.

Cách sửaXóa đúng ba key bằng npm config hoặc sửa file có backup; không đụng config dự án.

08 / CURRENT REVIEW

Những việc còn nên xử lý.

Đây là backlog đề xuất, chưa được sửa trong source. Ưu tiên bảo mật và ownership trước polish.

P0Scope PATCH theo owner

Update hiện dùng WHERE id = ?. User đã đăng nhập có thể sửa Todo của user khác nếu đoán ID. Thêm AND user_id = ? với req.userId.

P0Chặn stored XSS

renderTodos() đưa todo.task trực tiếp vào innerHTML. Task chứa HTML/script có thể thực thi. Render bằng DOM + textContent hoặc escape output.

P0Không track database/token

todo.db đang được Git theo dõi và todo.rest chứa JWT thật. Ignore database runtime, bỏ token khỏi file và rotate secret/token nếu repo từng chia sẻ.

P1Chuẩn hóa status code

Login nên trả 200, PATCH nên trả 200, DELETE nên trả 200/204; 301 là redirect và không phù hợp.

P1Kiểm tra affected rows

PATCH/DELETE cần đọc result.changes; trả 404 nếu không có row thuộc user bị thay đổi.

P1Validate completed và id

Không bind undefined; chỉ chấp nhận ID nguyên dương và completed là 0/1 hoặc boolean được normalize.

P1Transaction khi register

User và Todo mặc định cần atomic. Nếu insert Todo thất bại, không nên để lại user nửa chừng.

P1Auth error an toàn

Dùng message chung cho “user không tồn tại” và “password sai”; map username trùng thành 409 thay vì 500.

P1Bearer token contract

Hiện app gửi raw token. Chuẩn phổ biến là Authorization: Bearer <token>; client và middleware phải đổi cùng lúc.

P1Sửa frontend auth errors

Code khai báo textError nhưng vẫn dùng global error; cần thống nhất và kiểm tra response.ok cho login/register.

P2Tránh fetch lặp

Sau auth, code gọi fetchTodos() rồi showDashboard() lại fetch lần nữa. Chỉ giữ một owner cho thao tác load.

P2Sửa static path

Route tường minh dùng src/public/index.html sai vị trí. Static middleware đang che lỗi. Dùng ../public/index.html hoặc bỏ route dư.

P2HTML & metadata

Đổi className thành class; cập nhật package description/main/test và xóa code demo đã comment.

Ranh giới quan trọng: JWT xác thực “ai đang gọi”; query có user_id mới quyết định “người đó được sửa record nào”. Authentication không tự động tạo authorization ở cấp tài nguyên.

10 / GLOSSARY

Từ khóa cần nhớ.

Một từ khóa tốt phải gắn với trách nhiệm cụ thể trong source hiện tại.

Middleware
Hàm chạy giữa request và route; có thể sửa request, trả response hoặc gọi next.
Router
Nhóm handler theo method/path và một domain như auth hoặc todos.
JWT
Token có chữ ký chứa claims; được verify, không mặc định được mã hóa.
Claim
Dữ liệu trong JWT, ví dụ user id, issued-at và expiration.
Authentication
Xác định người gọi là ai.
Authorization
Quyết định người đó được đọc/sửa record nào.
Prepared statement
SQL có placeholder; tách code SQL khỏi giá trị để bind an toàn.
Foreign key
Ràng buộc bảo đảm Todo chỉ tham chiếu tới user tồn tại.
Transaction
Nhiều thao tác database thành một đơn vị: cùng thành công hoặc cùng rollback.
Runtime validation
Kiểm tra dữ liệu thật khi request chạy; không tin JSON từ client.
HTTP contract
Method, path, header, body và response mà client/server cùng tuân thủ.
Stored XSS
Dữ liệu độc hại được lưu rồi chèn lại bằng innerHTML và thực thi trong browser.
